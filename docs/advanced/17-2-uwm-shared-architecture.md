# 17-2 UWM 的动作—视觉共享架构

17-1 已把一条交互分成当前观测、实际动作块和真实未来画面。UWM 不直接把像素与关节数值塞进同一个数组，而是先把不同数据变成 Transformer 可处理的 token，再由共享网络学习它们的关联。本节沿输入、共享计算、输出的顺序解释架构，并回答一个常被省略的细节：网络究竟怎样为**每个动作位置和每个视觉位置**给出噪声估计。

## 三路输入的角色不同

当前观测 $o_t$ 是已知条件。例如推杆与物体当前在哪里，来自已有相机画面；它不作为本次需要从噪声恢复的未来答案。UWM 用视觉编码器处理当前的相机观测，形成供共享网络读取的条件特征。论文实现采用 ResNet-18 编码当前多相机、多帧观测，具体尺寸与相机数量是实现选择，不是联合式建模的定义。[UWM 原论文架构部分](https://arxiv.org/html/2504.02792)

第二路是动作块。每个未来控制位置有一组数值，例如末端位移、转角及夹爪命令；训练时先按所选噪声进度加噪，再用小型多层感知机把每个位置的数值映射为动作 token。第三路是真实未来画面。UWM 用**固定的 VAE 图像编码器**将未来画面压缩为可解码的视觉潜变量，先在潜变量上加噪，再切成视觉 token。这里的 VAE 潜变量服务于画面生成，最后可解码回图像；它不是第 15 章 LeWM 训练的 JEPA 特征，也不是机器人动作标签。

共享 Diffusion Transformer（扩散 Transformer，DiT）同时处理带噪动作 token 和带噪视觉 token；当前观测特征及两路噪声进度告诉网络“场景是什么”和“每路内容被破坏到什么程度”。两个噪声进度分别记为 $k_a$、$k_v$。它们是**扩散过程的噪声等级**，不是动作块第几步，也不是视频第几帧。论文还使用辅助的 register token 让两种模态交换信息；这些 token 是网络内部可学习的中间表示，不对应某条真实机器人命令或某一帧监督答案。

## Transformer 最后怎样得到两种噪声

可把动作块想成未来 16 个控制位置、每步 7 个数的教学形状。加噪后有 16 个带噪动作向量；投影层把它们变成 16 个动作 token。共享 Transformer 中，每个位置的隐藏向量读取其他动作位置、视觉 token 和当前观测条件。最后，**动作输出层**对每个动作位置的隐藏向量做一次映射，给出该位置 7 个噪声估计值；合起来形状仍是 $16\times7$。这是逐位置输出，不是自回归地先生成第 1 步动作、再生成第 2 步，也不是由 Transformer 直接“猜一段动作”后才去计算噪声。

视觉侧采取相同的对应原则：每个视觉 token 的隐藏向量经**视觉输出层**映射到它所代表的潜变量块的噪声数值；这些块重新拼合后，与被加噪的未来视觉潜变量同形状。训练时恰好知道两路各自加入了哪份随机噪声，所以可以逐位置核对预测。共享的是处理动作与视觉之间关系的主体网络，两类输出的数值形状和职责仍各自独立。上面的 $16\times7$ 只是帮助看清输出形状的教学例子，不是 UWM 论文对所有机器人的固定动作规格。

为什么不是“DiT 必须自回归”？Transformer 是一种让 token 交换信息的网络结构；自回归是规定某个输出只能看此前位置的**生成方式**。UWM 在一次去噪调用中同时估计整段动作与未来视觉各位置的噪声，采样器再多次调用同一个网络修正整段内容。这里反复迭代的是**噪声等级**，而非沿机器人的真实时间顺序一次只追加一个动作 token。这与第 12 章的动作 Diffusion 数据流一致，只是现在多了一条未来视觉支路。
