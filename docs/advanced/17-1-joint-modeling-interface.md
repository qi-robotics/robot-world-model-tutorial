# 17-1 联合建模的对象与交互数据

第 16 章的级联式系统在**使用时**保留一段明确的中间结果：先依据目标形成未来计划，再由另一模块将计划转换成动作。第 17 章改问：一条真实机器人交互本来就同时记录了动作和动作造成的后果，能否让模型一起学习这两类信息，并根据需要分别回答“该怎样行动”与“行动后会怎样”？本章以 [Unified World Models（UWM）原论文](https://arxiv.org/html/2504.02792)为贯穿实例。这里先把学习对象和时间配对讲清，再进入网络结构。

## 级联与联合比较的是哪件事

在桌面推物任务中，当前画面显示推杆位于物体左侧，控制器执行一次向右推动，随后相机拍到物体移动。第 16 章的级联路径从**目标**出发，按“当前观测与目标 → 未来计划 → 动作”运行；而这段交互记录可支持另两种提问：仅看当前观测，示范中的动作是什么？给定当前观测和实际动作，真实未来是什么？联合式模型让这两种答案共同参与训练，使用时再决定哪一项已知、哪一项需要生成。

因此，“联合”主要描述**学习关系**，不等于“只剩一个物理网络文件”，也不等于“每次推理都同时输出动作和视频”。UWM 的具体做法是在共享的扩散 Transformer 中同时学习动作与未来视觉，再通过不同输入条件选择推理任务。图 17-1 是两种数据流的对照，不应读成“上面旧、下面新”或“联合在所有任务上必然更好”。

## 一条交互记录怎样形成两份答案

设 $o_t$ 是执行前的观测，$a_{t:t+H_a-1}$ 是接下来实际执行的动作块，$v_{t+1:t+H_v}$ 是与这段动作对应的真实后续画面。$H_a$ 表示动作位置数，$H_v$ 表示取样的未来画面数；机器人控制频率与相机采样频率未必相同，所以两者不必相等。记录的时间关系是：先取得 $o_t$，在随后一段时间执行动作，再取得属于同一时段的未来画面。两份训练答案分别是**实际动作块**和**真实未来画面**。

例如教学数据可记录“当前画面中推杆中心在像素 12、物体中心在像素 22；控制器随后实际命令末端右移 $0.02$ 米；下一次画面中推杆中心到了像素 22，物体尚未移动”。后一个画面说明本次只是接近，不能把“向右”一律当作物体已被推动。像素数描述画面位置，米描述机器人动作；两者须分别保存，不能拿像素冒充控制量。若把另一段推动的动作错配给这张未来画面，模型就会得到互相矛盾的动作—后果训练样本。

动作与未来是两份答案，却不是两个彼此无关的标签。动作可以影响未来画面；而在相似当前画面下，未来是否出现接触，也为理解动作与视觉变化的关系提供信息。但仅从这种相关记录训练，不能自动保证模型具备可靠的物理因果判断；仍需在未见轨迹和改变动作的对照中核对。

## 无动作标签的视频还能教会什么

有的视频只记录“之前看见什么、之后看见什么”，没有控制器动作。它能提供未来视觉变化的训练材料，却不能凭空变出“真实执行了哪个关节命令”的标签。UWM 允许把这类视频与带动作的机器人记录共同用于训练：缺失动作的位置以完全噪声占位，模型仍能从真实前后画面学习视觉分支。16 章的视频规划器也能利用无动作视频，但两者训练目标与使用接口不同；不能仅因都看过视频就把它们归为同一种架构。[UWM 论文训练方法](https://arxiv.org/html/2504.02792)

本节还须划清目标条件的边界：UWM 论文中的基本接口以当前观测为条件，动作与未来视觉是可切换的生成对象。它**不自动**把任意中文目标转换成目标画面，也不免除第 07、12 章的动作边界检查。17-2 将说明动作和未来画面怎样进入同一个网络；17-3 再说明两份答案怎样在一次训练迭代中使用。
