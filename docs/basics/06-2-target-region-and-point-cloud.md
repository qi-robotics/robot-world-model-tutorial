# 06-2 从目标区域到三维点云

06-1 算出的是画面中**一个像素**对应的三维表面点。可是“红杯”不是单个像素：杯沿、杯身和被遮住的部分处在不同位置，目标中心像素甚至可能没有有效深度。本节把第 03～05 章得到的视觉目标与深度图连接，说明怎样从区域内的可靠测量得到物体的可见三维证据。

## 先选出哪些像素属于目标

视觉模块可提供不同形式的输出，每种形式对后续几何的帮助不同：

| 视觉输出 | 示例 | 几何模块得到什么 | 仍需注意什么 |
| --- | --- | --- | --- |
| 检测框 | 一块矩形区域 | 大致搜索范围 | 框内同时可能有杯子与背景 |
| 分割掩码 | 每个像素属于杯子与否 | 可筛选杯子表面像素 | 杯沿、遮挡边界可能分错 |
| 关键点 | 杯沿或把手的二维坐标 | 少数有明确语义的位置 | 对应像素可能无深度，点名须固定 |
| 已估计的物体位姿 | 位置加旋转 | 更接近规划器所需对象状态 | 需定义物体自身坐标系并核验误差 |
| 空间视觉 token | 多个区域的特征 | 供后续模型读取对象线索 | 不是可直接代入反投影的像素坐标 |

语言中的“红杯”可以帮助视觉模型选择候选区域，但语言向量自身不给出深度。若画面中有红杯和红色托盘，目标区域选错以后，几何公式仍会认真计算出**错误物体**的三维点；几何正确不能弥补识别错误。

## 从目标掩码收集有效三维点

假设分割掩码 $M(u,v)$ 标明哪些像素属于目标，深度图为 $d(u,v)$。只对 $M(u,v)=1$ 且深度有效的像素使用 06-1 的反投影公式，就得到目标的可见点集合 $P_C=\{{}^{C}p_i\}_{i=1}^{N}$。单个点有 $(X_C,Y_C,Z_C)$ 三个坐标；若附上 RGB 颜色，每点变成六个数。点云形状可以是 $[N,3]$ 或 $[N,6]$，并须注明它仍属于**相机坐标系**。若保留与原图逐像素对应的结构，也可表示为 $[H,W,3]$ 并另外保存有效位；删除无效点后，才变成长度随画面变化的 $N$ 行数组。

例如杯子掩码覆盖 900 个像素，其中 70 个深度无效，最终只有 830 个有效点。不能用零深度填补那 70 个位置再一起求平均，那会把估计向相机原点拉偏。实践 06-01 的图中有人工制造的无效深度小洞，正是为了在点云图上看到“掩码内有像素”与“该像素有三维测量”并不是同一回事。

~~~mermaid
flowchart LR
    I["RGB 图像"] --> M["目标检测或分割<br/>选出候选像素"]
    D["对齐的深度图"] --> V["有效深度筛选"]
    M --> V
    V --> B["按相机内参逐点反投影"]
    K["当前分辨率的内参"] --> B
    B --> P["目标可见表面点云<br/>相机坐标 / 米"]
~~~

图中的“目标候选像素”与“有效深度像素”必须取交集。只用彩色分割会缺距离；只用深度会分不清哪片表面属于语言指定的杯子。

## 点云能说明什么，不能说明什么

点云记录的是**当前视角测到的表面**，不等于完整物体。杯子背面、被夹爪遮挡的杯沿和桌面下方都可能不可见；透明或反光材质也可能产生空洞。目标点云的平均位置通常是“可见表面点的平均”，不是物体的几何中心。若只看见杯子一侧，平均点会偏向这一侧。用检测框中心的单点深度同样容易落在空洞、桌面或后方背景上。

可以先在目标内部选择远离边界的有效像素，再查看深度是否集中于合理范围；遇到离群点，可用中位数或局部表面拟合形成较稳健的**表面位置估计**。但不能把“取中位数”说成自动恢复完整杯子中心。若任务要求杯沿姿态、杯子轴线或抓取接触面，还需更多点、几何先验或多视角观测。多视角融合又要求相机位姿和采集时间对齐，否则运动中的杯子会被错误叠加。

点云也可进一步放入三维网格，得到体素表示。体素便于对局部占据作规则计算，却要付出分辨率成本：三个方向的网格间距都减半，同一空间范围内的格子数约变成八倍。本章不把体素当作抓取的必需步骤，只借它说明三维表示也有精度与内存的取舍。

实践 06-01 的后半段把目标掩码中全部**有效**深度像素反投影，并绘出目标表面点云。读结果时先数清哪些像素被剔除，再核对三维坐标轴；最后解释为什么这片点云尚不能直接交给基座坐标下的控制器。
