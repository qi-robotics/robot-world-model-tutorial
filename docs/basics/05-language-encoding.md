# 05 语言编码：从自然语言到任务表示

第 04 章讨论了视觉编码器怎样保留物体与位置的信息。可是只看同一张桌面图像，机器人仍不知道应该拿起红杯、推动蓝杯，还是避开它们。语言指令提供任务目标；模型要使用它，先得把文字变成数值，再保留对象、动作、关系和约束，最后与视觉内容建立对应。

本章沿“**文字序列 → 任务表示 → 图文对应 → 可检查的机器人接口**”展开。语言编码不等于模型已经理解了现场，也不等于机器人已经完成任务；每一步的输入、输出与能力边界都要分开检验。

| 小章 | 核心问题 |
| --- | --- |
| [05-1 文本数值化与批处理](05-1-tokenization-embedding-and-mask.md) | 字符串怎样变成 token id、向量和 batch？补齐与 mask 为何影响整句结果？ |
| [05-2 机器人指令的任务表示](05-2-instruction-and-task-representation.md) | 词序、上下文、动作、对象和约束怎样形成任务条件？否定与歧义为什么不能靠关键词表解决？ |
| [05-3 图文对齐与共同表示](05-3-image-text-alignment.md) | 两个编码器的输出怎样通过配对数据建立可比较的语义空间？整图匹配为何不等于目标定位？ |
| [05-4 从语言表示到机器人任务接口](05-4-language-interface-and-checks.md) | 语言表示怎样接给视觉与动作模块？怎样验证目标、条件和执行结果没有被混为一谈？ |

三份配套 Notebook 分别与前三节对应，最后一节将它们的检验结果合在一起。它们使用人工构造的小数据演示接口，不复现预训练语言模型或完整 CLIP。Notebook 在新标签页打开，便于保留正文对照。

读完本章，应能从一条中文指令追踪到任务向量或 token 级特征，再说明为何还需要图文定位和真实执行检查。下一章会把已定位的图像区域转换成机器人可用的三维目标。
