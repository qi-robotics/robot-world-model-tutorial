# 07-2 力、触觉与接触状态

上一节用编码器和运动学确定了夹爪的位置，但“夹爪到了杯子旁边”与“夹爪已经稳定抓住杯子”不是同一句话。图像中的边缘可能互相遮挡，末端位置也可能因标定误差而偏离。机器人还需要力和触觉等接触证据，并把这些证据放回动作发生的时间顺序中。

## 从靠近到抓稳：传感器各能说明什么

假设机器人正在抓杯子。接近阶段，相机和末端位姿可判断夹爪与杯子的相对位置，却不能单凭两者在图像中重合就断定发生了接触。手指碰到杯壁时，腕部力传感器可能测到力的变化，指尖触觉阵列可能在局部出现压力。夹爪继续闭合后，只有观察杯子是否跟随夹爪移动、触觉分布是否稳定，以及夹爪开度是否停止变化，才能更有把握地判断抓取是否稳定。

| 信号 | 通常提供什么证据 | 单独使用时的局限 |
| --- | --- | --- |
| 腕部六维力/力矩 | 三个方向的力和三个方向的力矩，常用于发现碰撞、承载或推压 | 多处接触混在一起，未必能定位到哪根手指 |
| 指尖触觉 | 手指表面的局部压力或接触分布，部分传感器还可反映剪切变化 | 覆盖范围、分辨率和标定随硬件而异 |
| 夹爪开度与电流 | 手指是否继续闭合、驱动负载是否改变 | 电流上升也可能来自机构阻力，不能直接等同“抓稳” |
| 视觉与物体跟踪 | 杯子是否随夹爪移动、是否从手中掉落 | 遮挡、帧率与光照会使接触瞬间不清楚 |

六维力/力矩常写作 $w_t=(F_x,F_y,F_z,M_x,M_y,M_z)$。前三项单位为牛顿，后三项为牛·米；这六个数还必须注明在哪个坐标系测量。例如腕部传感器自身坐标系的 $F_z$，不能不经变换就当成基座坐标系的竖直力。接触力的正负号同样由坐标轴方向决定。将它与相机、关节读数合并时，还应记录测量时间，而不只是把六个数字接到向量尾部。

## 接触和滑移为什么要看连续变化

一次力峰值只能说明某时刻受力改变，不足以说明杯子是否已被稳定抓住。下面的时间线把动作、测量和判断分开：

~~~mermaid
flowchart LR
    A[夹爪接近杯子<br/>图像与末端距离缩小] --> B[手指初次接触<br/>局部触觉与受力变化]
    B --> C[夹爪继续闭合<br/>开度变化减慢]
    C --> D[提起杯子<br/>杯子应随夹爪移动]
    D --> E[若发生滑移<br/>触觉位置或杯子相对位置改变]
~~~

例如，提起时夹爪高度增加了 $2$ 厘米，杯子的高度却几乎没变，这比单独看到一帧“夹爪靠近杯子”更能说明抓取失败。另一种情况是杯子先跟着移动，随后指尖压力位置逐渐偏移且杯子相对夹爪下降；这提示可能正在滑移。两种判断都依赖**前后变化**，因此要保留连续观测，而不是把每个时刻独立地标注为“接触/未接触”。

工程中可以为一个经过标定的传感器设置阈值，用来触发减速或重新检查，但阈值不是接触的通用定义。空载偏置、传感器噪声、软物体、工具重量以及接触方向都可能改变读数。更重要的是，传感器只能提供证据：力增大可能是杯壁接触，也可能是夹爪撞上桌面。需要结合视觉位置、本体状态和刚刚下发的动作解释它。

## 为模型保留可用的接触记录

训练样本中可以保存原始力/触觉读数，也可以保存由这些读数计算出的接触标记，但两者不应混为一谈。接触标记是某个检测规则的结果；原始读数允许后来检查规则是否误判。若触觉设备不存在，应显式记录“该模态缺失”，而不能用全零压力冒充有效测量，因为零也可能表示传感器正常工作且没有受力。

另一处容易出错的是时间对齐。若动作 $a_t$ 在相机曝光后才发出，随后力传感器出现峰值，不能把峰值错排为发出动作**之前**的观测，否则模型会在训练时提前看见未来。第 07-5 节将把各模态的时间戳、有效位与动作放进统一数据契约。

接触证据回答的是“发生了什么”。下一节转向另一个问题：模型输出的数字究竟要求机器人**做什么**。
