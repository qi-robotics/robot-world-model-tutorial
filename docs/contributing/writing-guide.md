# 写作指南

本教程的章节不是独立百科词条。默认叙事是：

```text
提出问题
→ 简单方案
→ 暴露局限
→ 引出新方法
→ 解释输入输出
→ 最小实验
→ 连接世界模型
→ 留下下一章的问题
```

## 开始前

- 先读 [学习路线](../roadmap.md)，确认这一章补的是哪一个能力缺口。
- 直接编辑 `docs/` 下对应 Markdown，用 `mkdocs serve` 预览。
- 不要删除模板标题；可以按章节需要增补小节，但不要把页面写成只有 TODO。

## 章节模板

教程正文页应保持这些标题，便于读者形成肌肉记忆：

1. 本章解决什么问题
2. 学习目标
3. 前置知识
4. 从上一章遗留的问题开始
5. 直观理解
6. 数学形式
7. 输入、输出与张量形状
8. 模块结构
9. 最小实现
10. 可视化与实验
11. 常见误区
12. 它在机器人世界模型中的位置
13. 本章小结
14. 下一章

## 写作约束

!!! warning "不要在占位阶段虚构结果"
    可以写问题、符号、形状和结构，不要编造准确率、消融数字、未核对的论文结论或“业界公认”的排名。

- 中文为主，术语第一次出现时给出英文。
- 符号一旦引入，后续章节保持不变；冲突时先改 [术语表](../glossary.md)。
- 公式使用 `\( ... \)` 或 `$$ ... $$`。
- 图示优先 Mermaid；复杂图再放到 `docs/assets/diagrams/`。
- 代码示例必须标明它只是最小接口，还是可运行实验。
- 内部链接使用 Markdown 文件路径，例如 `[CLIP](../basics/clip.md)`。

## 推荐语气

- 学术、克制、具体。
- 用“它解决了上一章的哪个缺口”代替“它非常重要”。
- 用输入输出表代替形容词。

## 提交前

- 运行 `mkdocs build --strict`
- 确认上一章 / 下一章链接仍然有效
- 若新增术语或文献，同步更新术语表和参考文献页
